# Frontend validation record — lab-quadratic-funding web

Worker-side validation of the static frontend in `web/` and its export in `dist/`. This is the
worker's own report, not an independent network certification. Publication checks (fixed CID, named
entrypoint, asset hashes, RPC chain id, contract code) run later in the control plane and are not
claimed here.

## 1. Scope and assumptions

- **Pages/flows reviewed:** the single page `dist/index.html`: wallet discovery/connection, wrong
  network → switch/add chain, MTCH balance and allowance, standalone approve, read-only pool rate,
  rounds list with projects/contributions/estimated match, approve → contribute, approve → fund,
  creator-only register, finalize, payout claim, funder reclaim, per-round activity from events,
  create round, contracts footer.
- **Build/export:** `web/` (Vite 6.4.3, React 19.3.0, TypeScript 5.9.3, viem 2.56.9, Node 24.21.0)
  → `dist/` with `base: "./"`. Export: 6 files, 578,591 bytes plus the manifest (bundle 551 kB,
  viem being most of it).
- **Deployment binding:** `dist/imd-deployment.json` is generated by `web/plugins/imd-deployment.ts`
  from byte copies of the handoff (`web/deployment/handoff.json`) and network file
  (`web/deployment/network.json`) plus `docs/abi/*.json`; the app loads that file and the referenced
  ABIs at runtime and holds no other address/chain/ABI map. ABI canonical keccak hashes were verified
  against the handoff's `abiHash` (LaunchToken `38880b8e…37bee`, QuadraticFunding `0b1afd09…c91ee`)
  in a scratch script, in the build plugin (build fails on mismatch) and in `config.test.ts`.
- **Inferred choices:** no in-page swap, per the approved workflow ("no in-page swap"); the page
  explains that MTCH comes from swapping Sepolia ETH in the launch pool and shows a read-only
  quote through the manifest's Uniswap v4 quoter address (the only Uniswap address the page uses).
  Light theme only, system font stack, sentence case, one indigo accent. Rounds are listed newest
  first. Event history is loaded on demand per round (bounded 10,000-block windows from the
  deployment block 11791425) to keep RPC load small. `DESIGN.md` is at `docs/DESIGN.md` because the
  repository root is outside this assignment's write scope.
- **Exclusions:** no WalletConnect (no project id supplied; browser wallets via EIP-6963 and
  `window.ethereum`); no dark theme, localization or animation beyond the press scale.

## 5. Untested live-chain behaviour and limitations

- **No real transaction was broadcast** (not authorised): approve, fund, contribute, createRound,
  register, finalize, claim and reclaim were exercised only against the fake chain (mocked
  JSON-RPC and wallet) in unit tests and in the browser. Live gas estimation, wallet UI, real
  reorgs and pending-transaction timing are unverified.
- Live Sepolia reads were verified for the current state only (zero rounds); the round/project
  rendering against live data is verified only with the mocked chain.
- The quoter call was verified live (returns a value) but the launch pool's real price impact and
  the correctness of the rate for larger sizes were not assessed; the page labels it as a read
  before slippage and offers no swap.
- Public RPC log-range limits vary; `eth_getLogs` uses 10,000-block windows and was verified only
  against the fake chain.
- Not performed: screen-reader session, physical device, browser-native zoom (CSS `zoom: 2` proxy
  only), RTL, forced-colors, APCA measurement, dark theme (none exists).
- The MCP browser tool was not used for the export (no managed preview, `file://` cannot load a
  module script); the evidence comes from the bounded foreground Playwright script described above.
